# ADR-0005：Word 字段生命周期与 finalizer 策略（TOC / SEQ / REF / PAGE）

- 状态：Accepted
- 日期：2026-08-15
- 关联风险：R-006（字段未刷新）、R-027（finalizer 依赖）、R-014（WPS/LibreOffice 差异）、R-028（LO 视觉偏差）、R-015（Word 修复提示）
- 事实输入：`spikes/phase0/fields/REPORT.md`、`spikes/phase0/fields/results/no-repair.json`、`spikes/phase0/fields/results/word-refresh.json`、`spikes/phase0/fields/results/lo-refresh-diff.json`、`spikes/phase0/fields/results/fields-inventory.json`、`spikes/phase0/fields/results/structure-checks.json`、`docs/update/CURRENT_STATE_AUDIT.md`

## 1. 背景与问题

ThesisForge 渲染器已产出真 Word 字段（AGENTS.md §1.5）：TOC 字段、图/表/公式 SEQ 编号、REF 交叉引用、页脚 PAGE/NUMPAGES，均带 cached result 与 dirty 标记，`settings.xml` 写 `<w:updateFields w:val="true"/>`（`docs/update/CURRENT_STATE_AUDIT.md` §2.4）。但「生成了字段」不等于「用户看到正确结果」——字段何时求值、由谁求值、求值失败时显示什么，构成字段生命周期问题（R-006）。

Phase 0 fields spike（2026-08-15，Word 16.107.2 / LibreOffice 26.2.3.2，双模板双样本）实证了生成态字段在各软件中的真实行为，暴露三类问题：

- **D-11：TOC 无 cached 条目**。生成态 TOC 字段 `TOC \o "1-3" \h \z \u` 的 cached result 为空；Word 打开时不会自动填充空 TOC（即使导出 PDF 也为空），用户点「否」拒绝更新即看到空目录（`results/no-repair.json`、`results/word-refresh.json`，物理证据 `samples/*-word-declined.pdf`）。
- **Word 首开必弹模态确认框**：「该文档包含的域可能引用了其他文件。是否更新该文档中的这些域？」不点击文档打不开，自动化场景被阻塞 150s 以上（REPORT §4/§5）。
- **现有 LibreOffice finalizer 破坏结构校验**：LO 无头刷新能填充 TOC，但改写字段语义并导致 `openxml_validate` 失败（`results/lo-refresh-diff.json`），当前 final-auto 路径产物过不了项目自己的门禁。

需要决策：cached result 策略、finalizer profile 体系、SEQ `\r` 钉值取舍的显式化、字段状态的可观测性。

## 2. 决策

### 2.1 所有字段始终写 cached result，并为 TOC 增加 cached 条目

- REF/SEQ/PAGE/NUMPAGES 维持现状（cached result 恒写）；
- **TOC 字段新增 cached 条目**：构建期由 finalizer/编译期填充真实条目文本与页码作为缓存，修复 D-11——任何不求值字段的路径（Word 点「否」、多数预览器、直接导出 PDF）都应显示非空目录。
- 责任人：渲染器 + finalizer 模块；完成时点：final-auto profile 修复（§2.2）随 Phase 7 落地前，TOC cached 填充必须先行可用。

### 2.2 三个 finalizer profile

| profile | 语义 | 状态 |
|---|---|---|
| **draft** | 生成态直出：updateFields + dirty 均开启；接受 Word 首开模态弹窗，并在用户文档中明确说明「首次打开请选择'是'更新域」 | 立即可用（现状即此，补文档说明） |
| **final-auto** | LibreOffice 无头刷新填充 TOC/字段缓存后交付 | ~~降级为 preview 用途~~ **2026-08-15 解除降级**（§5.3 第 2 项修复完成，见 §7）：LO 刷新破坏校验问题已修复，产物过 openxml_validate 且字段指令与渲染器原状一致；仍不作版式权威（R-028，final-word 为 GA 权威路径） |
| **final-word** | Word 自动化（macOS AppleScript / Windows COM）刷新并保存，**GA 权威最终件路径** | Phase 7 建设；spike 已证明技术可行 |

### 2.3 SEQ 保留 `\r` 钉值

- 生成态与 final-word 产物中，SEQ 指令保持 `SEQ TF_Figure_1 \r N \* ARABIC` 形式，编号钉死在编译期计算值（确定性优先）；
- 该取舍（用户在 Word 端增删图片后 F9 不会顺序重排编号）**写入 `docs/MARKDOWN_SPEC.md` 与用户文档**，并在 build report 中声明；
- 注意：final-auto（LO 刷新）会剥掉 `\r`（见 §3.4）——2026-08-15 起 finalizer 在刷新后按指令比对还原 `\r` 钉值（§7），final-auto 产物恢复编译期钉值语义；该剥离曾是其降级为 preview 的原因之一。

### 2.4 build report 记录字段状态

- 每次构建输出字段清单与状态：字段类型/数量、cached 是否填充、dirty/updateFields 开关状态、finalizer profile 与执行结果、校验通过与否——使「字段是否正确」可审计而非靠人工开 Word 确认（R-006 预防措施）。

### 2.5 执行条款（谁、在什么版本前、做什么）

| 时限 | 责任方 | 动作 |
|---|---|---|
| Phase 7 前 | 渲染器维护者 | TOC 字段写入 cached 条目（修复 D-11），补 XML 结构测试 |
| 即刻 | 文档维护者 | 用户文档说明 draft 首开弹窗行为（「首次打开请选择'是'更新域」）；SEQ `\r` 钉值取舍写入 `docs/MARKDOWN_SPEC.md` 与 `docs/USER_MANUAL.md` |
| final-auto 解除降级前 | 渲染器 + QA | 修复 §5.3 第 2 项的 LO 刷新破坏（样式补齐 + 指令矫正），验收标准：`*-lo-refreshed.docx` 过 `openxml_validate`（exit=0）且字段指令与渲染器原状一致；修复前 final-auto 仅作 preview |
| Phase 7 | 应用层维护者 | final-word provider（AppleScript/COM）建设并纳入 doctor 检测 |
| 每次构建 | 构建服务 | build report 输出字段状态（§2.4），纳入 JSON 输出与 qa 门禁 |

## 3. 决策理由

以下事实全部来自 `spikes/phase0/fields/REPORT.md` 及对应 results JSON（脚本机械产出，可复跑；Word 侧由 AppleScript 驱动实测，全程关闭不保存、样本 sha256 不变）。

### 3.1 cached result 是最终显示的兜底，且质量合格

- 生成态字段清单（`results/fields-inventory.json`）：SEQ 为 `SEQ TF_Figure_1 \r 1 \* ARABIC` + cached "1"；REF 为 `REF tf_fig_architecture \h` + cached 编译期显示文本（`图1-1`、`(2-1)`、`表2-1` 等，complete 样本 8 个、minimal 1 个）；PAGE/NUMPAGES 只在 footer，cached 恒 "1"。
- Word 刷新前后逐字段比对：**全部 REF/SEQ 的 result 完全一致**（按指令匹配，`results/word-refresh.json`）——cached 值与 Word 重算结果一致，「显示有兜底，求值有权威」的组合成立（REPORT §7）。
- PAGE/NUMPAGES 由 Word 排版引擎动态求值：拒绝更新状态下导出的 PDF（`samples/*-word-declined.pdf`）页脚仍显示真实值（如 `第i页/共6页`，罗马/阿拉伯混排正确），cached "1" 无害（REPORT §5/§7）。
- **反例即 TOC**：cached 为空时，Word 点「否」后 TOC 保持空，导出 PDF 也为空（REPORT §5 对「是否自动填充」的否定回答）——D-11 必须修。

### 3.2 updateFields 与 dirty 各自独立触发 Word 模态弹窗

变体矩阵实测（3 格对照变体 × 2 样本，结论一致，`results/no-repair.json`、REPORT §5）：

| 变体 | updateFields | fldChar dirty | 打开时弹窗 |
|---|---|---|---|
| 原样本 | ✓ | ✓ | 是 |
| `-no-updatefields` | ✗ | ✓ | **是** |
| `-keep-updatefields-nodirty` | ✓ | ✗ | **是** |
| `-no-updatefields-nodirty` | ✗ | ✗ | **否（静默打开）** |

弹窗为模态确认框（否/是），不点击则打开不完成；变体打开后字段快照与原样本相同（TOC 空、cached 照常显示），证明 dirty/updateFields 不影响 cached 显示语义。推论：draft profile 无法避免首开弹窗，只能靠文档说明；要「双击即开无打扰」必须两者都剥掉（此时 TOC 只能依赖 cached 条目——再次印证 §2.1）。同会话内多次回答后 Word 会停止弹窗，但抑制规则未确定，ADR 不依赖它（REPORT §5 补充观察）。

### 3.3 SEQ `\r` 钉值在 Word 端生效，确定性可保

- 实测：生成态 SEQ 指令带 `\r`，Word 中全量 `update field` 后 result 仍为 "1"——**编号被钉死在编译期计算值**（`results/word-refresh.json`，REPORT §5「SEQ `\r` 钉值对 F9 的影响」）。
- 语义推论：用户后续在 Word 里增删图片后 F9，编号不按文档顺序流动重排——这是「编译期编号权威」的确定性语义，与项目「Parser 不算编号、Compiler 统一计算」的架构一致（IR_MODEL_DESIGN §1.1 G3）；代价必须显式告知用户（§2.3）。

### 3.4 LO 刷新可填充 TOC，但当前破坏字段语义与结构校验

`results/lo-refresh-diff.json`（两样本一致，REPORT §6）：

- 已证实收益：TOC 被填充为真实条目；`settings.xml` 的 `w:updateFields` 被移除（Word 首开不再弹窗）；120s 内完成。
- 已证实破坏：
  - **SEQ `\r` 钉值被剥**：`SEQ TF_Figure_1 \r 1 \* ARABIC` → `SEQ TF_Figure_1 \* ARABIC`（cached 不变），与 §2.3 的确定性取舍直接冲突；
  - **TOC 指令被改写**：`TOC \o "1-3" \h \z \u` → `TOC \f \o "1-3" \h`（丢 `\z \u`，新增 `\f`）；
  - 页眉页脚部件被整体重写；PAGE cached 出现评估值 `0`（封面节，与 Word 显示语义可能不一致）；
  - **openxml_validate 失败（两样本均 exit=1）**：LO 写 TOC 条目时引用了渲染器 styles.xml 未定义的样式（complete 样本缺 `FootnoteCharacters`/`IndexLink`/`TOC1`/`TOC2`/`TOC3`；minimal 样本缺 `IndexLink`）——缺口是「渲染器样式覆盖面 < LO 输出引用」，styles.xml 还原机制本身正常（刷新后 sha256 一致）。
- 结论：final-auto 在这些破坏修复前只能作 preview；修复方案见 §5.3 第 2 项。

### 3.5 final-word 技术可行性已实证

AppleScript 驱动 Word 实测（`results/word-refresh.json`，REPORT §5）：`update` TOC + 逐字段 `update field` 全部成功、0 失败（update_log 计数 complete=50 / minimal=5）；TOC 被填充且**指令保持 `TOC \o "1-3" \h \z \u` 不变**；SEQ `\r` 保留；REF/SEQ result 刷新前后一致；刷新后导出 PDF 成功。局限：Mac Word 无 header/footer 对象模型、需处理模态弹窗与沙盒授权、依赖用户机器装 Word——故不作默认路径，作 GA 权威最终件路径（R-027 退路一致）。

## 4. 备选方案与拒绝理由

### 4.1 剥掉 updateFields + dirty，永远静默打开 ——拒绝为默认

- 变体实证两者都剥掉后 Word 静默打开（§3.2），代价是字段永不自动更新：TOC 若再有缓存缺失/过期就是永久错误显示，违反「求值有权威」原则；可作为未来的显式选项，不作默认。

### 4.2 以 LO 刷新产物直接作为最终交付 ——修复前拒绝

- §3.4 的全部破坏项：SEQ 钉值丢失（确定性语义被静默改变）、TOC 指令失 `\z \u`、结构校验 exit=1。把过不了自家门禁的产物命名为「final」不可接受（R-006/R-015）。

### 4.3 用普通文本伪造 TOC/编号（一次性静态渲染）——拒绝

- 违反 AGENTS.md §1.5「不要用普通文字伪造目录、题注编号、交叉引用」；用户在 Word 中失去字段的全部可更新性与导航能力。

### 4.4 依赖 Word 打开时自动更新（不写 cached）——拒绝

- §3.1/§3.2 已证：Word 不会静默更新，是先弹模态框；点「否」即空 TOC；多数预览器与直接导出 PDF 不做字段求值。无 cached 等于把正确性交给用户操作。

## 5. 后果

### 5.1 正面

- D-11 修复后，任何消费路径（预览器、PDF 导出、拒绝更新的 Word）都能看到非空目录与正确引用文本（R-006 核心缓解）；
- 三个 profile 把「草稿迭代」「自动预览」「权威交付」三类场景的字段语义显式分开，final-word 作为 GA 权威路径与 R-007/R-028 的「Word 主基准」原则一致；
- SEQ `\r` 钉值从隐藏实现细节升级为显式语义（IR_MODEL_DESIGN §5.3 已把 `pinned_result` 建模进 FieldRequest），确定性取舍可审计；
- build report 字段状态让字段问题进入可测试、可回归的质量体系（R-016）。

### 5.2 负面（已接受的代价）

- draft 用户首开 Word 必见模态弹窗，体验有损，只能靠文档说明与「点'是'」引导缓解；
- final-auto 在修复前降级为 preview，期间自动交付路径缺位；
- final-word 依赖用户机器安装 Word 并处理弹窗/沙盒授权（REPORT §10：外部卷授权、AppleScript 下标迭代等工程细节），不适合 CI 默认路径；
- SEQ `\r` 钉值意味着 Word 端编辑后编号不自动流动，需文档明确预期。

### 5.3 后续行动

1. **TOC cached 条目填充**（渲染器/finalizer，修复 D-11）：构建期写入真实条目文本与页码作为 TOC cached result；补对应 XML 结构测试。
2. ~~**修复 LO 刷新破坏结构校验的问题**（final-auto 解除降级的前提）~~ **已完成（2026-08-15，见 §7）**：
   - 渲染器无条件补齐 LO 会引用的样式（`TOC1-3`/`IndexLink`/`FootnoteCharacters`），或在 finalizer 后修补（REPORT §8 建议）；
   - 阻止 LO 剥 SEQ `\r`、改写 TOC 指令丢 `\z \u`（刷新后按指令比对并矫正，或改用 LO 可保留指令的刷新方式）；
   - 验收标准：`*-lo-refreshed.docx` 过 `qa/tools/openxml_validate.py`（exit=0）且字段指令与渲染器原状一致。
3. **final-word finalizer provider 建设**（Phase 7）：AppleScript/COM 刷新 + 保存，处理模态弹窗与授权，纳入 R-027 的 doctor 检测。
4. **build report 字段状态**（§2.4）落地，进入 JSON 输出与 qa 门禁。
5. **文档**：SEQ `\r` 钉值取舍写入 `docs/MARKDOWN_SPEC.md` 与 `docs/USER_MANUAL.md`；draft 首开弹窗说明写入用户文档。
6. **附带修复（spike 过程发现）**：`office_refresh.py:592` darwin 硬编码 `/tmp` 改为 `temporary_root=None`（尊重 TMPDIR，D-09）；`qa/tools/no_repair_open.py` 区分「字段更新确认框」与「修复提示」（REPORT §9 问题清单第 1 条）。

## 7. 实施记录

- 2026-08-15：**TOC cached 条目已完成**（§2.1 决策要点一 / §5.3 第 1 项，修复 D-11）。编译期 `compile_document` 把各级标题汇总为 renderer-neutral 的 `TocEntryInstruction`（文本/级别/书签）挂到 `TocInstruction.entries`；DOCX 渲染器在 TOC 字段 separate 与 end 之间逐条写入缓存条目段落（TOC 1/2/3 样式 + `w:hyperlink` 锚定标题书签 + 右对齐制表位 + 内嵌 `PAGEREF` 字段，cached 页码占位 "1"——编译期无排版引擎，求值类消费者刷新后得真实页码），字段指令 `TOC \o "1-3" \h \z \u` 与 dirty/updateFields 语义不变。TOC1-3 段落样式改为无条件写入 styles.xml（模板无 toc 配置时用确定性默认），同步缓解 §3.4 中 LO 刷新引用未定义样式导致的 openxml_validate 失败。配套 XML 结构测试与 `qa/tools/openxml_validate.py` 门禁全过（`tests/test_docx_renderer.py` 新增 3 项、`tests/test_acceptance.py` 补 TF-D4-TOC-019 断言，全套 550 通过）。
- 2026-08-15：**LO 刷新破坏已修复，final-auto 解除降级**（§5.3 第 2 项 / §2.2）。修复内容：
  1. **样式补齐（渲染期预置，选此方案而非 finalizer 后修补）**：渲染器在 `styles.py` 无条件定义 `Index Link` / `Footnote Characters` 字符样式（`LO_REFRESH_CHARACTER_STYLE_NAMES`），与 TOC1-3 恒定义同 precedent；因为刷新后 styles.xml 会被还原为渲染器原件，样式必须出自渲染器才能在还原后仍可解析。实测修复前 HUT 模板样本刷新后缺 `IndexLink`/`FootnoteCharacters`（§3.4 中 example 模板另缺 TOC1-3，已被上一条覆盖），修复后 LO 的全部样式引用均有定义。

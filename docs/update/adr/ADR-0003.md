# ADR-0003：LaTeX→OMML 公式转换路线 —— 扩展手写子集 + Provider 抽象

- 状态：Accepted
- 日期：2026-08-15
- 关联风险：R-008（LaTeX→OMML 覆盖不足）、R-024（第三方许可证）、R-002（Pandoc 分发）、R-016（测试层次）
- 事实输入：`spikes/phase0/omml/REPORT.md`、`spikes/phase0/omml/results/coverage.json`、`spikes/phase0/omml/results/omml_assertions.json`、`spikes/phase0/omml/results/openxml_validate_report.json`、`docs/update/CURRENT_STATE_AUDIT.md`

## 1. 背景与问题

ThesisForge 必须把用户书写的 LaTeX 数学式转换为真 OMML（`m:oMath`），不得以图片或纯文本伪造公式（AGENTS.md §1.5）。现状（`docs/update/CURRENT_STATE_AUDIT.md` §2.3）：

- `src/thesis_forge/core/math.py`（277 行）为手写 LaTeX 子集递归下降解析 → 语义数学树 → OMML；未知命令抛 `UnsupportedMathError`；
- 审计时子集覆盖率未知（无 corpus 量化），且发现编号排版缺陷（D-10）。

`docs/MATH_SPEC.md:41` 明确要求：renderer 不得把不支持的公式静默替换为纯文本；模板 schema 已规定 `unsupported_latex` 默认 `error`（`docs/update/TEMPLATE_PACKAGE_SCHEMA_V2.md:535`，「不得静默降级」）。

Phase 0 spike（2026-08-15）以 50 条语料（`spikes/phase0/omml/corpus/formulas.yaml`，学科分布：计算机 11、数学 15、统计学 6、电子 4、机械 3、物理 4、管理学 4、多学科通用 3；难度：简单 31 / 中等 18 / 困难 1；每条含 id、latex、语法类别、典型场景、display/inline 用法）对三条候选链路逐条实测：A. 项目手写子集、B. pandoc（texmath → 原生 OMML）、C. latex2mathml + MML2OMML.XSL。所有数字由脚本机械产出并落盘 JSON，可复跑（REPORT §1）。需要决策：V1 公式链路走哪条路线，目标覆盖率如何定义，外部依赖与许可证如何处置。

## 2. 决策

1. **V1 继续扩展手写子集路线**（`core/math.py` 路线）：
   - 以 50 条 corpus 为基准定义并文档化 supported subset，按 §5.3 的优先级扩充；
   - 目标：V1 内把 corpus 覆盖率从 48% 提升到 ≥95%（即补齐 §5.3 第 1 项的 P0/P1 清单，实质是重写一个 texmath 子集，REPORT §7 问题清单第 1 条）。
2. **未支持命令显式报错**：凡 corpus 之外的命令一律抛 `UnsupportedMathError` 并阻断 build（`unsupported_latex: error` 语义），禁止静默降级为纯文本；支持的命令清单写入 `docs/MATH_SPEC.md`。
3. **转换器抽象为 provider 接口**：`LatexMathConverter` 收敛到 `MathConverter` 协议（`convert(latex, *, display) -> OMML 子树`，错误结构化），项目内置手写 provider 为默认且唯一必需实现。
4. **pandoc 允许作为可选外部转换 provider**：仅在用户自行安装 pandoc 时可用，不随包分发、不进入编译依赖（与 ADR-0001 同一原则）；其产出仅为 `m:oMath` 片段，编号/书签/REF 包装仍由 `renderers/docx/equations.py:render_equation` 承担（包装点已在 spike 中确认集中于此）。
5. **latex2mathml + MML2OMML.XSL 路线仅记录、不采用**（许可证原因，见 §4.3）；spike 资产与实证数据保留备查。
6. **行内数学（`$...$`）是否进 V1 的决策留给 Phase 2**，与 ADR-0001 的 inline rule 工作一并评估；本 ADR 只覆盖块级 `::: equation` 链路。

## 3. 决策理由

以下数字全部来自 `spikes/phase0/omml/REPORT.md` 与 `results/coverage.json`（脚本机械产出，可复跑）。

### 3.1 三条链路的 corpus 实测覆盖率

spike 环境：macOS（arm64）、Python 3.14.4（`.venv`）、pandoc 3.8.2.1、latex2mathml 3.81.0；三条链路对同一语料逐条转换，结果机械落盘（REPORT §1）。

| 链路 | 成功率 | 关键事实 |
|---|---|---|
| A. 手写子集 | **24/50（48.0%）** | 失败 26 条 = 24 条 `UnsupportedMathError` + 2 条 `MathSyntaxError`（非用户错误，是文法限制） |
| B. pandoc 3.8.2.1 | **49/50（98.0%）** | 唯一失败 eq22 裸 `\\` 无环境换行；产物 49 个 `m:oMath`（`m:m`×3、`m:d`×7、`m:eqArr`×1、`m:nary`×17） |
| C. latex2mathml 3.81.0 + MML2OMML.XSL | MathML **50/50（100%）** → OMML **49/50** | 唯一失败 eq21（aligned）：上游 bug，裸 `&` 未转义进 MathML，可预处理绕过 |

（`results/coverage.json`：`thesisforge.success=24, coverage=0.48`；`pandoc.success=49, coverage=0.98`；`both_fail=[]`——pandoc 失败的 eq22 手写子集虽「成功」但为静默错渲染，见 §3.3 与 §5.3 第 2 项；`thesisforge_fail_but_pandoc_ok` 共 26 条，构成 §5.3 第 1 项的扩展清单。）

另需说明手写子集 2 条 `MathSyntaxError` 的性质：`\sin^2 \theta` 报 `Unexpected '^'`、`\log_2 n` 报 `Unexpected '_'`，根因是函数参数解析只吃掉一个原子、上下标无法先挂到函数名上（REPORT §3.1）——属文法修复项而非覆盖率天花板。

### 3.2 手写子集的失败结构清晰、可补齐

失败命令分布（REPORT §3.1）：`\begin` 环境（pmatrix/vmatrix/cases/aligned）3 条、`\int` 2 条、`\left` 2 条、`\mathrm` 2 条，另有 15 个单发命令（`\approx \binom \ddot \det \eta \forall \lim \nabla \nu \partial \prod \sim \subset \text \vec`）各 1 条。失败集中在有限的几类语义（nary 运算符、自适应括号、环境、直立文本、accent、扩展希腊字母），且 OMML 侧所需的 `m:nary/m:d/m:m/m:eqArr/m:acc` 元素形态已被 pandoc 产物实证（REPORT §3.2），扩展有明确参照物。

分类对照（thesisforge / pandoc，REPORT §3.4）进一步说明差距是「点状」而非「面状」：四则/分式/根式 4/4 已持平；上下标 2/3、希腊字母 2/3、综合 5/6、行内混排 2/2（仅转换层）接近；缺口集中在求和/积分/极限/乘积 3/7、矩阵/行列式 0/2、分段函数 0/1、括号自适应 0/2、`\text`/`\mathrm` 0/3、运算符 1/7、accent 2/4、三角/对数/指数 2/4——每一类都对应明确的 OMML 元素与已知文法修复点。

意外发现：`\eta` 不在 `GREEK_SYMBOLS`（其余 20 个小写希腊字母都在），属个别遗漏而非设计边界，补齐成本低（REPORT §3.1、§5.3）——深度学习最常用的学习率记号恰好踩中（eq06）。

### 3.3 手写链路的工程质量已被验证

`build_sample.py` 把子集可转换的 22 条 display 公式（`::: equation {#eq:*}` 容器，模板 `templates/schools/example-university/2026.yaml`，equation 编号为 chapter 模式）走完整管线（`parse_markdown` → `validate_document` → `compile_document` → `DocxRenderer.render`）构建为 `output/sample.docx`（`results/omml_assertions.json`）：

- `m:oMath` 总数 22 = 预期，逐条落在对应公式段落内；
- 编号公式 SEQ field 22 个，`w:instrText` 形如 `SEQ TF_Equation_1 \r 3 \* ARABIC`（字段名规则 `TF_{Kind}_{chapter}`，`core/compiler.py:180`）；书签 22 个，`w:bookmarkStart` 名形如 `tf_eq_eq01_arith_frac`（`tf_` 前缀 + id 非法字符转 `_`，`core/compiler.py:155`）；
- 逐条断言（oMath + SEQ + 书签同段落）`per_equation_all_ok=true`；
- `qa/tools/openxml_validate.py` 结构校验 **13/13 通过，退出码 0**（`results/openxml_validate_report.json`）。

即手写路线不仅「能转」，而且编号、书签、交叉引用包装、OOXML 结构门禁全链路已验证——这是外部 provider 不具备的下游整合度（REPORT §7 问题清单第 6 条：外部后端只给 OMML 片段，语义树支撑编号/校验/预览）。

这也意味着扩展子集时每新增一类命令，都可复用同一套断言与门禁做验收，测试基建无需重建。

### 3.4 零依赖与确定性

- **零新增依赖**：手写路线纯 Python、进程内执行，不引入 253 MB 二进制（R-002）或许可证不明资产（R-024）；与 ADR-0001 的分发原则一致。
- **确定性**：转换逻辑完全由项目代码决定，无外部进程行为差异；与项目「同一输入逐字节一致」的构建目标兼容。
- **语义树的下游价值**：`MathNode` 语义树承载「哪些符号、是否分段/矩阵」等信息，支撑编号、校验、预览与未来的可访问性；外部后端只给 OMML 片段，这些信息需要另行重建（REPORT §7 问题清单第 6 条）。

## 4. 备选方案与拒绝理由

### 4.1 B. pandoc 作为转换后端 ——拒绝为默认路线，降级为可选 provider

- 覆盖率 49/50（98%）即用即得，但代价是 253 MB/平台二进制进入分发链、按平台签名、锁版本——正是 ADR-0001 已拒绝的 R-002 形态；公式链路没有豁免该决策的理由。
- pandoc 只产出 `m:oMath` 片段：SEQ 编号、书签、`\r` 钉值、REF 交叉引用仍需项目自行包装（包装点集中在 `renderers/docx/equations.py:render_equation`，REPORT §7 问题清单第 2 条），即引入 pandoc 并不省掉与字段生命周期（ADR-0005）的整合工作。
- 行为不可控项：eq22 失败时 pandoc 退出码仍为 0，需 stderr + `m:oMath` 计数双重判据判定失败（REPORT §3.2）——作为默认后端会把诊断可靠性绑在外部进程的输出约定上。
- 结论：抽象为 provider 接口后，pandoc 作为**用户自装的可选外部 provider** 保留价值（大批量存量 LaTeX 文档迁移等场景），但永不进入默认编译路径。

### 4.2 C. latex2mathml + MML2OMML.XSL ——仅记录，不采用

- 技术上实测可行：latex2mathml 50/50 转 MathML，XSLT 后 49/50 得良构 OMML（REPORT §3.3）；
- eq21（aligned）失败属上游 bug：latex2mathml 把对齐符 `&` 未转义写进 MathML（`<mi>&</mi>`），产物非良构 XML，可预处理（先转义裸 `&`）绕过；
- 版本陷阱已实测排除：meTypeset 镜像的 "Beta Version 070708" 副本是 **XSLT 2.0**，libxslt（lxml/xsltproc）只支持 1.1，转换退化成纯文本拷贝不可用；必须用 Office 正式版（XSLT 1.0）；
- **拒绝原因是许可证（R-024）**：MML2OMML.XSL 是 Microsoft 随 Office 分发的专有文件，**未附开源许可**（spike 副本镜像自 PaddlePaddle/PaddleX 仓库，151707 字节，本身无许可声明，REPORT §8 来源说明）；再分发需法务确认。自写等价转换的工作量参照物是该 XSL 约 150 KB / 数千条模板规则（REPORT §7 问题清单第 3 条）——远高于扩展手写子集的成本；
- 即便许可证解决，该路线仍引入「MathML 中间格式 + XSLT 引擎（libxslt 版本约束）」两层外部行为面，确定性弱于纯 Python 手写转换；
- 结论：不作为 V1 路线；若未来法务确认授权或社区出现许可清晰的等价物，可通过 provider 接口接入，本决策不封死该可能。

### 4.3 直接禁用复杂公式、只支持现有 24 条子集 ——拒绝

- 48% 对学位论文不可用：矩阵、分段函数、`\int`、`\left\right`、`\mathrm` 均为论文高频（REPORT §6 P0 清单「缺了基本没法用」），不补齐等于公式功能名存实亡。

## 5. 后果

### 5.1 正面

- 保持零依赖、确定性、进程内的编译链路，与 ADR-0001 的分发原则一致；
- supported subset 以 50 条 corpus 显式定义并随版本演进，用户对「什么能写」有可查清单（`docs/MATH_SPEC.md`），R-008 的「明确 supported subset」预防措施落地；
- 「显式报错优于静默降级」的行为与 `unsupported_latex: error` 默认值（`TEMPLATE_PACKAGE_SCHEMA_V2.md:535`）及 MATH_SPEC「不得静默替换为纯文本」要求闭环；
- provider 接口为未来接入 pandoc/其他后端留出受控扩展点，且不改 renderer；
- 现有 22 条编号公式的 OMML/SEQ/书签断言与 openxml_validate 13/13 门禁成为扩子集时的回归基线（R-016）。

### 5.2 负面（已接受的代价）

- 扩子集实质是重写一个 texmath 子集：parser/model/renderer 三层都要动，每类命令需配 OOXML 结构测试（REPORT §7 问题清单第 1 条，AGENTS.md §5），工作量高于「直接调 pandoc」；
- 覆盖率在扩展完成前低于外部方案（48% vs 98%），期间用户遇到未支持命令会得到 build error 而非公式——这是显式选择的行为（不得静默降级），需要靠报错信息与文档缓解；
- 手写文法自有 bug 需修复（见 §5.3 第 2 项），修复前存在「转换成功但渲染错误」的保真度风险（REPORT §5）；
- 公式编号排版的既有缺口（D-10：编号仅 `\t` 分隔、无右对齐制表位，`renderers/docx/equations.py:148`）不在本 ADR 范围内，但扩子集触及 `render_equation` 时应一并评估。

### 5.3 后续行动

1. **按失败榜优先级扩子集**（REPORT §6 P0/P1，Phase 6 前完成）：
   - `\begin{pmatrix|bmatrix|vmatrix|cases|aligned}` 环境（3 条失败，含矩阵/行列式/分段/多行对齐）；
   - `\int \prod \lim` 含上下限（nary，2 条失败）；
   - `\left \right` 自适应括号（2 条失败）；
   - `\mathrm` / `\text`（含中文注释，2+1 条失败）；
   - 函数名上下标文法修复（`\sin^2`、`\log_2`、`\max_a`，即现有 2 条 `MathSyntaxError` 的根因）；
   - 扩展希腊字母与运算符单发 15 个（`\approx \binom \ddot \det \eta \forall \lim \nabla \nu \partial \prod \sim \subset \text \vec`）。
2. **修复两个保真度 bug 与 \eta 遗漏**（REPORT §5，随扩展一并完成）：
   - 函数参数只吃一原子：`\log p(x_i)` 渲染为 `m:func(log, p)`、括号 `(x_i)` 游离在 func 外（eq10 实测 `fName=log`、`e=p`）——语义结构错误，需把括号组纳入函数参数；
   - 静默字面化：eq22 裸 `\\` 被当转义字面量接受，OMML 中出现内容为 `\` 的 `m:r`——`\\` 应作为语法错误或换行语义处理，不应静默通过；
   - `\eta` 补入 `GREEK_SYMBOLS`。
3. **建立 OMML 结构黄金测试**：对照样本 XML 断言（spike 的 `omml_assertions.json` 模式固化为测试），因为 spike 证明「转换成功」会掩盖静默错误（REPORT §7 问题清单第 4 条）。
4. **定义 MathConverter provider 接口**并把 pandoc provider 实现为可选外部工具（`doctor` 检测、版本记录、失败结构化诊断）。
5. **inline math（`$...$`）支持决策留给 Phase 2**：当前语法与管线均不支持行内数学（`inline_math_converted=false`，两条 inline 公式以纯文本残留，REPORT §4；`INLINE_TOKEN_RE` 不含 `$`），需与 ADR-0001 的 markdown-it inline rule 工作一并评估。

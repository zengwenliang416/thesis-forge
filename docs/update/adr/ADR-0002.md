# ADR-0002：Template Package v2（reference.docx + 可选 shell.docx + 属性级 precedence + 显式迁移）

- 状态：Accepted
- 日期：2026-08-15
- 关联 Phase：Phase 0（决策）→ Phase 3–5（实现）
- 关联风险：R-004 / R-005 / R-012 / R-020 / R-026

## 1. 背景与问题

v0.3 模板是单个 YAML 文件（`src/thesis_forge/templates/model.py`，686 行，
`docs/TEMPLATE_SPEC.md`），全部版式——页面几何、封面 11 个固定 field、
正文/标题/题注样式、页眉页脚文字与边框——都要用 YAML 字段重建
（`docs/update/CURRENT_STATE_AUDIT.md` §2.5，债务 D-14：样式实际来自
python-docx 默认模板，`renderers/docx/document.py:76`）。这带来四个问题：

1. **表达力不足（R-004）**：真实学校模板包含复杂封面、声明页、校徽图片、
   多节页眉页脚与现成 Word 样式，纯 YAML 重建既脆弱又不可维护；
   RISK_REGISTER 将 R-004 评为 High × Critical。
2. **样式来源不可信**：现状渲染器以 python-docx 默认包起建文档，再用
   `configure_styles()` 把 YAML 值写进同名样式。spike 实证该写入是
   无条件的（`spikes/phase0/docx-template/REPORT.md` §1.2.3：Normal 的
   firstLineIndent 从 None 被改写为 480 twips）。一旦引入 reference.docx
   作为样式来源而不定义优先级，模板承诺即失效。
3. **复杂前置页无落点**：封面/声明/目录区与正文区的节属性（页码格式、
   页眉页脚引用）不同，需要可选的 shell.docx 承载；但 DOCX 包合并涉及
   rId 冲突、部件名冲突、样式冲突、包级单例（settings/theme/fontTable/
   docProps）归属等已实证会破坏包结构的风险（R-005，Medium × Critical）。
4. **演进无保护**：v0.3 → 任何新 schema 都必须防止「旧模板被静默按新
   规则解释」（R-026）。

Phase 0 spike（`spikes/phase0/docx-template/`，报告同目录 `REPORT.md`）
对两条候选路线做了实证；`docs/update/TEMPLATE_PACKAGE_SPEC_V2.md`
（概念设计，下称 SPEC_V2）与 `docs/update/TEMPLATE_PACKAGE_SCHEMA_V2.md`
（可实现级 schema，下称 SCHEMA）已把决策落点为 D-1～D-7。本 ADR 记录
最终决策。

## 2. 决策

采用 **Template Package v2**，替代 v0.3 单 YAML 模型：

1. **包形态**：目录形态（authoring）+ `.tftpl` 打包形态（distribution，
   受约束的确定性 ZIP 快照 + `manifest.json`）。包内容为
   `template.yaml` + `reference.docx` + 可选 `shell.docx` + `assets/` +
   `layouts/` + `styles/aliases.yaml` + `citations/` + `fixtures/` +
   `expected/` + `provenance.yaml` + `CHANGELOG.md` + `LICENSES/` +
   `README.md`；最小包为 `template.yaml` + `reference.docx` +
   `provenance.yaml` + `fixtures/minimal/` + `README.md`
   （SCHEMA §1.1）。
2. **职责划分**：`reference.docx` 承载 styles/theme/fontTable/page setup/
   header-footer/numbering base/settings/default language；`template.yaml`
   只表达结构语义、规则与白名单映射；`shell.docx` 承载复杂前置页与
   投递锚点（书签对，`tf_body`/`tf_toc`/`tf_bibliography`）。
3. **样式 precedence 采用 SCHEMA 决策 D-1**：全部版式属性三分类、互不重叠——
   A 结构语义类（page/sections/numbering/regions/toc 域开关/fields 策略）
   以 template.yaml 为唯一权威；B 样式覆盖白名单（§3.8 body、§3.9
   headings 的 page_break_before/keep_with_next、§3.18 toc.levels、
   §3.19 bibliography 的 hanging_indent/line_spacing）YAML 显式值生效
   并回写构建产物内样式、产生 `yaml-overrides-style`（info）诊断；
   C 纯样式类（字体/字号/颜色/边框等）以 reference.docx 为唯一权威，
   YAML 不得表达（`extra=forbid` 自然拒绝）。优先级总序：
   **B 类 YAML 显式值 > reference.docx 样式 > 渲染器内置默认**；
   渲染器禁止无条件改写 reference.docx 样式、禁止就地编辑模板文件。
4. **能力分期**：Alpha 只用 reference.docx；shell.docx（锚点合并）为
   Beta 能力——这是 R-005 退路的直接落实。未实证的合并路径（部件级
   rels 递归、numbering/footnotes 双侧 id 占用）在 Alpha 显式拦截报错
   （`unsupported-shell-feature` 等），不做部分合并。
5. **PackageEditor 按 spike 搬运清单实现**（SCHEMA §5.3 即决策落点）：
   以 OPC 包操作为核心（ZIP 条目 + lxml），不依赖 python-docx 文档模型
   做合并；导入节点引用的 rId 全部重映射（allocator = shell 现有最大
   rId 编号 +1 递增）；部件名冲突按数字后缀递增重命名并同步改写 rels
   Target；styles 按引用 + basedOn/next/link 闭包最小搬运，冲突按 token
   对齐后 **shell-wins**（决策 D-3），token 无映射冲突报
   `style-conflict-unmapped`（warning）并完整记录台账；footnotes part
   在 shell 缺失时整体搬运（w:id 不重映射）；`[Content_Types].xml`
   复制对应 Override；**不合并** settings/theme/fontTable/docProps
   （决策 D-5：settings/theme 归 shell，fontTable 归 reference，
   settings 仅 evenAndOddHeaders/updateFields/mirrorMargins 三个白名单
   字段由 YAML 语义写入）。每次合并输出台账并入 build manifest；
   合并后必须过 openxml_validate + L3 锚点/样式/relationship 检查 +
   目标应用冒烟。region → anchor 分槽投递依据 Compiler 输出的 region
   边界 manifest（决策 D-4），禁止「首个分节符之后全部导入」的近似。
6. **v0.3 → v2 迁移采用 SCHEMA 决策 D-7**：提供
   `thesisforge template migrate`，自动映射 + 逐字段三态台账
   （`migrated` / `manual-required` / `dropped`，仅无语义损失字段允许
   dropped），产物立即过 L1–L3 lint；承诺「无静默失真」，不承诺
   「零人工」。`schema_version` 非 `2` 一律 `unsupported-schema-version`
   error 拒绝，v2 加载器不 fallback（SCHEMA §8.3）。
7. **安全策略（R-020）**：`macro_policy: forbid`、`external_relationships:
   forbid`（可选 allowlist）；宏/外部关系/OLE/外部字段代码在 L1 lint 与
   PackageEditor 合并两层强制；不提供「忽略安全警告继续」选项。

## 3. 决策理由（实证依据）

以下来自 `spikes/phase0/docx-template/REPORT.md` 与其产物
（`output/reference-summary.json`、`output/shell-summary.json`、
`output/merge-report.json`），全部可复现（报告 §6 给出复现命令）。

**路线①（reference.docx 作样式来源）成立**：

- 以 HUT 学校 YAML 为蓝本编程注入后，TF Body / TF Heading 1-4 /
  TF Abstract / TF Bibliography / TF Figure Caption / TF Table Caption /
  TF Equation / TF Code Char 共 **12 个样式**全部随包携带，新文档可直接
  按名使用；`output/reference-inheritance.docx` 经
  `qa/tools/openxml_validate.py` 校验 **13/13 通过**（报告 §0、§1.1）。
- 页面设置（A4、左 30mm/右 25mm/上下 25mm、页眉 15mm、页脚 17.5mm、
  docGrid lines linePitch 400=20pt）、默认页眉（校名 + 0.5pt 下边框）
  与页脚（PAGE 域）均随 sectPr/独立部件继承（报告 §1.1）。
- `default_template_has_tf_styles=false`：python-docx 默认包不含 TF
  样式，reference.docx 确实是样式的唯一来源而非碰巧提供（报告 §1.1）。
- theme 字体惰性已实证：所有样式 rFonts 为显式值、docDefaults 已改写为
  宋体/Times New Roman，theme 的 Calibri/Cambria 对本模板无影响
  （报告 §1.1）——这支持 D-5「theme 不合并」。
- 已知 API 缺口可控：fontTable/theme 只暴露 blob、`w:pgNumType` 与书签
  无公开 API，需少量底层 XML 工具函数（报告 §1.2）。

**路线②（shell.docx 锚点合并）成立但有明确边界**：

- 合并产物 `output/merged.docx`：openxml_validate **13/13 通过**，
  soffice 无头转 PDF 成功（**372,941 字节**），LibreOffice 可无修复打开
  （报告 §0、§2.3）。
- 搬运台账实证：导入节点引用 **5 个 rId** 全部重映射
  （rId11→rId14 … rId21→rId18）；部件名冲突（header2.xml/footer2.xml/
  media/image1.png）按数字后缀重命名；footnotes.xml 整体搬运并登记
  rId19 + Content Types Override；导入内容引用 14 个样式、闭包后 22 个、
  其中 **8 个与 shell 冲突**（Normal、Heading1-3 及各自 Char、
  DefaultParagraphFont）；shell 既有 **13 条 relationships 全部原样
  保留**；合并后 3 个 sectPr（lowerRoman(1) → upperRoman(1) →
  decimal(1)）逐项断言符合预期（报告 §2.1–§2.3）。
- **rId/部件名冲突是必然事件而非边界情况**：双方同出 python-docx 默认
  包，rId1-8 段完全重叠（报告 §3.1–§3.2）——任何合并实现都必须有
  allocator，这正是第 2.5 条强制 carry-list 的原因。
- **compiled-wins 会回流污染 shell 前置页**：compiled 的 Normal 带
  firstLineIndent=480，替换后 shell 封面占位段落出现首行缩进
  （报告 §2.3）——这是 D-3 选择 shell-wins 的直接证据。
- **合并确定性**：allocator 采用「最大编号 +1」规则，相同输入产出相同
  结果（ZIP 时间戳除外）（报告 §4.8）——支撑 R-019 确定性要求。
- 未实证路径（部件级 rels 递归、双侧 numId/footnote id 占用）在 spike
  中以 `NotImplementedError` 显式拦截（报告 §3.6–§3.7），schema 将其
  落为 OQ-2/OQ-3 并在 Alpha 报错——与 R-005 退路「不支持的特性报错，
  不做部分合并」一致。

**schema 落点已就绪**：SCHEMA 的 D-1（precedence 三分类）、D-3
（shell-wins）、D-4（region manifest 分槽投递）、D-5（包级单例归属）、
D-7（migrate 三态台账 + schema_version 严格拒绝）均直接引用上述实证，
本 ADR 将其提升为已接受决策。

## 4. 备选方案与拒绝理由

1. **继续扩张 v0.3 单 YAML**：封面已靠 11 个固定 cover field 硬撑
   （CURRENT_STATE_AUDIT §2.5），复杂声明页、校徽、多节页眉页脚无法
   稳定重建；且会诱导 YAML 扩张为 Word 克隆语言——SPEC_V2 §2 非目标
   与 R-004 退路（「不将 YAML 扩展成任意 OOXML DSL」）均明确拒绝。
2. **整份复制学校下发的 Word 文件当模板**：等于把模板系统退化为文件
   拷贝，无校验、无继承、无迁移、无安全边界；SPEC_V2 §2 明示为非目标。
3. **样式冲突 compiled-wins**：spike §2.3 实证其回流污染 shell 前置页
   （Normal 首行缩进 480 twips 出现在封面）；降级为
   `template lint --merge-simulation` 的诊断比对模式（SCHEMA §5.3 D-3）。
4. **用 python-docx 文档模型做跨包合并**：python-docx 没有跨包合并
   API，fontTable/theme 等部件只暴露 blob（spike §4.1）；PackageEditor
   必须直接操作 ZIP 条目 + lxml。
5. **Alpha 即启用 shell.docx**：R-005 为 Medium × Critical，合并的坑
   （rId 冲突、final sectPr 丢弃、书签成对清理、sectPr 子元素顺序）
   虽全部实证可控，但未实证路径仍需补 spike；按 R-005 退路分期，
   Alpha 只用 reference.docx。
6. **v2 加载器兼容解释 v0.3（尽力解析）**：违反 SPEC_V2 §20「旧模板
   不能被静默按新 schema 解释」与 R-026 退路；采用显式
   `template migrate`（D-7）。

## 5. 后果

### 正面

- 学校样式承诺可信：样式唯一来源是 reference.docx，B 类覆盖可归因
  （逐属性来源落 build manifest，SCHEMA §4.2），C 类不可被 YAML 触及。
- 模板作者不需修改 Compiler 核心代码（SPEC_V2 §1），配合 style token
  与 CI 静态检查构成 R-012（学校特例污染 Renderer）的预防。
- 模板包有安全边界（§5.5 两层强制）、有 provenance/许可证（R-024）、
  有确定性打包（D-6，R-019）、有显式迁移（D-7，R-026）。
- 合并行为有实证台账范式（`output/merge-report.json`），后续 lint 与
  排障有据可依。

### 负面 / 代价

- 模板制作成本上升：作者需准备 reference.docx 与 provenance，最小包
  也要过 L1–L3；需要 `template migrate` 与文档降低门槛。
- PackageEditor 是新的核心组件，合并台账、allocator、闭包搬运都有
  实现与测试成本；未实证路径（OQ-2/OQ-3）需补 spike 才能解锁。
- shell-wins 下前置页样式治理粒度未最终定（OQ-5），需随第一个真实
  学校 shell 模板复盘。
- `Document(reference.docx)` 就地编辑风险（spike §1.2.1）要求渲染器
  永远在副本上工作，属新的纪律性约束。

### 后续行动

1. 按 SCHEMA §1/§3 实现 v2 loader 与 L1–L5 lint（Phase 3）。
2. 实现 PackageEditor（carry-list、台账、校验闭环）与 Compiler region
   manifest 输出（D-4）；Alpha 拦截 OQ-2/OQ-3 路径（Phase 4–5）。
3. 实现 `template migrate`（D-7）并把 `templates/schools/` 两份 v0.3
   模板迁移为 v2 目录形态包，迁移复盘固化 OQ-7。
4. 补 spike：部件级 rels 递归（OQ-2）、numbering/footnotes 双侧 id
   重映射（OQ-3）、finalizer 与合并顺序（OQ-10）。
5. CI 增加模板 ID/学校名静态检查（R-012 预防，SCHEMA §4.2 末条）。

### 实施期决策（偏差点）

- **`body.line_spacing` 默认修正**：§3.8 表中 `line_spacing.type` 默认
  `fixed` 且 fixed 时 `value` 条件必需，若按字面默认出
  `LineSpacingSpec()` 则任何未声明 `body` 的包都无法通过校验，与 §4.1
  B 类「未写 → reference.docx token 样式生效」矛盾。实现取
  `line_spacing: LineSpacingSpec | None = None`（缺省 = 不覆盖），
  与 `bibliography.line_spacing` 的显式默认写法一致；建议回写 §3.8
  明确「line_spacing 整体可选」。
- headings level2–4 的 `style` 缺省回落为同级 token，因此最小合法包
  必须在 `styles.heading` 声明 1–4 级 token（测试 fixture 已按此构造）。

## 9. 实施记录（2026-08-15/16，Phase 3 切片 3：`.tftpl` 打包 + template migrate）

上一记录「已知遗留」中的 `.tftpl` 打包与 `template migrate` 两项关闭。

### 落地范围

- `src/thesis_forge/templates/v2/pack.py`：
  - `pack_package`：目录 → `.tftpl` 受约束 ZIP。确定性：entry 排序、
    规范化时间戳；**打包前置 lint L1+L2，有 error 拒绝产出**（D-6）；

    校验、逐 entry 流式 sha256（超限即中止）、**Zip Slip**（绝对路径/

  损失：显式值与 v2 默认值相同的字段）。幂等可重跑；目标目录非空拒绝
  覆盖；产物立即跑 lint L1–L3，报告随台账返回。
